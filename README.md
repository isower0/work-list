# Daily Work Tracker v2

เว็บแอปสำหรับบันทึกงานประจำวัน พร้อม Filter ตามวันที่และสถานะ
เก็บข้อมูลเป็นไฟล์ JSON บนเครื่อง รันเป็นเซิร์ฟเวอร์ Node.js
หรือ build เป็น `.exe` ไฟล์เดียวสำหรับ Windows ได้

## คุณสมบัติหลัก

- เพิ่ม / ลบ / เปลี่ยนสถานะงานได้แบบ realtime
- **แก้ไขชื่องานและรายละเอียด** ผ่าน modal (คลิกปุ่ม `แก้ไข`)
- **ลบหลายรายการพร้อมกัน** ด้วย checkbox + ปุ่ม `ลบรายการที่เลือก`
  (รองรับ Select All ทุกรายการที่ filter อยู่)
- 4 สถานะ: `ยังไม่ได้ทำ` `กำลังทำ` `กำลังทดสอบ` `เสร็จแล้ว`
- Filter ตามช่วงวันที่สร้าง และสถานะ (**เลือกได้หลายสถานะพร้อมกัน**)
- สรุปจำนวนงานแต่ละสถานะเป็นการ์ด
- สำรองข้อมูล (ดาวน์โหลด `tasks.json`) ผ่านปุ่มเดียว
- บันทึกเวลาสร้าง (`createdAt`) และวันที่ (`date`) อัตโนมัติ
  โดยใช้ Timezone `Asia/Bangkok`
- Responsive รองรับหน้าจอมือถือ
- Pack เป็น `.exe` ด้วย `pkg` ใช้งานได้โดยไม่ต้องติดตั้ง Node.js

## โครงสร้างโปรเจกต์

```text
daily-work/
├── server.js              # Express server + REST API
├── package.json           # dependencies + pkg config
├── data/
│   └── tasks.json         # ไฟล์เก็บข้อมูลงาน (สร้างอัตโนมัติ)
├── public/
│   ├── index.html         # หน้า UI
│   ├── app.js             # Frontend logic (fetch API)
│   └── style.css          # Styling
└── dist/
    └── work-list.exe      # Output จากคำสั่ง build:exe
```

## ความต้องการของระบบ

- Node.js 18 ขึ้นไป (สำหรับโหมด dev)
- Windows x64 (สำหรับไฟล์ `.exe` ที่ build ด้วย `pkg`)

## การติดตั้งและรัน

ติดตั้ง dependencies

```bash
npm install
```

รันเซิร์ฟเวอร์

```bash
npm run dev
```

เปิดเบราว์เซอร์ไปที่ <http://localhost:3000>

หากต้องการเปลี่ยนพอร์ต

```bash
set PORT=4000 && npm run dev
```

## Build เป็นไฟล์ .exe

```bash
npm run build:exe
```

ไฟล์จะอยู่ที่ `dist/work-list.exe` ดับเบิลคลิกเพื่อรันได้ทันที
ข้อมูล `tasks.json` จะถูกสร้างในโฟลเดอร์ `data/` ข้างไฟล์ `.exe`

## วิธีใช้งาน UI

**เพิ่มงาน** กรอกชื่อ รายละเอียด เลือกสถานะ แล้วกด `+ เพิ่มงาน`
วันที่สร้างจะใส่ให้อัตโนมัติเป็นวันนี้ (เวลาไทย)

**เปลี่ยนสถานะ** ใช้ dropdown ที่ท้ายแต่ละแถว ระบบจะบันทึกให้ทันที

**แก้ไขชื่อ/รายละเอียด** กดปุ่ม `แก้ไข` ที่แถวงาน จะเปิด modal ให้แก้
กด Enter ที่ช่องชื่อเพื่อบันทึก หรือ Escape เพื่อปิด

**ลบทีละรายการ** กดปุ่ม `ลบ` ที่ท้ายแถว

**ลบหลายรายการพร้อมกัน**

1. ติ๊ก checkbox ด้านซ้ายของแต่ละแถว หรือติ๊กที่หัว `รายการงานทั้งหมด`
   เพื่อเลือกทั้งหมดที่ filter อยู่
2. แถบสีเหลืองจะแสดงจำนวนรายการที่เลือก
3. กด `ลบรายการที่เลือก` เพื่อลบทั้งหมด หรือ `ยกเลิกเลือก` เพื่อเคลียร์

**Filter** เลือกช่วงวันที่ `จาก`–`ถึง` และคลิกปุ่มสถานะได้หลายอัน
(คลิกซ้ำเพื่อปิด) ถ้าไม่เลือกสถานะเลยคือแสดงทุกสถานะ
กด `ล้าง Filter` เพื่อรีเซ็ตทั้งหมด

**สำรองข้อมูล** กดปุ่ม `สำรองข้อมูล` ที่มุมขวาบนเพื่อดาวน์โหลดไฟล์

## REST API

Base URL: `http://localhost:3000`

| Method | Endpoint | รายละเอียด |
| --- | --- | --- |
| GET | `/api/tasks` | ดึงรายการงานทั้งหมด |
| POST | `/api/tasks` | เพิ่มงานใหม่ |
| PATCH | `/api/tasks/:id` | อัปเดต `status` / `name` / `detail` |
| DELETE | `/api/tasks/:id` | ลบงานทีละรายการ |
| POST | `/api/tasks/bulk-delete` | ลบงานหลายรายการพร้อมกัน |
| GET | `/api/backup` | ดาวน์โหลด backup `tasks.json` |
| POST | `/api/shutdown` | สั่งปิด server |

### POST /api/tasks

Request body

```json
{
  "name": "ชื่องาน",
  "detail": "รายละเอียด (optional)",
  "status": "todo",
  "date": "2026-10-09"
}
```

ค่า `status` ที่รองรับ: `todo` `doing` `testing` `done`
หากไม่ส่ง `name` หรือ `date` จะได้ `400 Bad Request`

Response `201 Created`

```json
{
  "id": "uuid-v4",
  "name": "ชื่องาน",
  "detail": "รายละเอียด",
  "status": "todo",
  "date": "2026-10-09",
  "createdAt": "2026-10-09T03:00:00.000Z"
}
```

### PATCH /api/tasks/:id

ส่งเฉพาะฟิลด์ที่ต้องการแก้ไข (ส่งได้ทีละอันหรือหลายอันพร้อมกัน)

```json
{
  "status": "done",
  "name": "ชื่องานใหม่",
  "detail": "รายละเอียดใหม่"
}
```

กฎการอัปเดต

- `status` รับเฉพาะค่า `todo` `doing` `testing` `done` (ค่าอื่นถูก ignore)
- `name` ถ้าเป็น string ว่าง/เว้นวรรคอย่างเดียวจะถูก ignore
- `detail` รับ string ใด ๆ (ค่าว่างถือว่าลบรายละเอียด)

Response คืน object ของงานที่อัปเดตแล้ว หรือ `404` ถ้าไม่พบ `id`

### DELETE /api/tasks/:id

ลบงานทีละรายการ Response `204 No Content`

### POST /api/tasks/bulk-delete

ลบงานหลายรายการพร้อมกัน

Request body

```json
{
  "ids": ["uuid-1", "uuid-2", "uuid-3"]
}
```

Response

```json
{
  "deleted": 3
}
```

หาก `ids` ว่างหรือไม่ใช่ array จะได้ `400 Bad Request`

## การจัดการข้อมูล

- ข้อมูลถูกเก็บเป็นไฟล์ JSON ที่ `./data/tasks.json`
  (อ้างอิงจาก `process.cwd()` ไม่ใช่ตำแหน่งของ `.exe`)
- โฟลเดอร์ `data/` และไฟล์ `tasks.json` จะถูกสร้างอัตโนมัติ
  ตอนรันครั้งแรกถ้ายังไม่มี
- สำรองข้อมูลได้ด้วยปุ่ม `สำรองข้อมูล` ที่หัวหน้าเว็บ
  หรือ GET `/api/backup` โดยตรง
- โฟลเดอร์ `data/` ถูก ignore ใน git อยู่แล้ว

## หมายเหตุ

- โปรเจกต์นี้ไม่มีระบบ auth ตั้งใจให้ใช้งานบนเครื่องตัวเอง
  ไม่แนะนำให้เปิด public
- ข้อมูลถูกเขียนทับทั้งไฟล์ทุกครั้งที่มีการเปลี่ยนแปลง
  เหมาะกับข้อมูลขนาดเล็กถึงกลาง (หลักพันถึงหมื่นรายการ)
